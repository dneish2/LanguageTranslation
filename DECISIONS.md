# Open decisions — resolved, with reasoning

Every open call from the local-first / model-diversity / voice work, with a resolution to act on.
David reviewed the reports and PRs on 2026-07-28 and endorsed the recommendations broadly; each
one below carries the reasoning so a future session can disagree with evidence rather than guess.

Anything marked **NEEDS DAVID** is genuinely blocked and must not be invented.

---

## 1. Whisper model size — `base` vs `small`

**Resolution: keep `base`, and add a documented escape hatch.**

`base` transcribes a 6.6 s clip in 0.6 s and was accurate on the test audio. `small` is slower and
better on accents and noise. The honest caveat: every measurement so far used a *synthetic* fixture
generated by a TTS model, which is unrealistically clean — exactly the audio that flatters a small
model.

Act on it:
- Keep `PASSAGE_WHISPER_MODEL=base` as the default.
- Document in `RESEARCH.md` that the choice is unvalidated on real speech.
- Do **not** switch to `small` on a hunch. If someone wants to settle it, record 5–10 real clips
  (accents, background noise, a phone mic) and measure word error rate both ways. That is a
  half-hour of work and would replace an assumption with a fact.

## 2. Should local voice default ON when the models are installed?

**Resolution: yes — default on when the models are actually present.**

It is both faster (1.51 s vs 7.62 s) and more private, so defaulting off penalises the better
option. The original argument for off was "don't silently change where someone's audio is
processed" — but *installing a speech stack and downloading voice weights is already an explicit
act*. Nobody does that by accident.

Act on it:
- `PASSAGE_LOCAL_VOICE` becomes tri-state: unset = **auto** (on if `faster_whisper` imports and a
  voice exists), `1` = force on, `0` = force off.
- The `/voice` page must name the engine that served the request, the same way the text workspace
  does. That transparency is what makes an automatic default acceptable rather than sneaky — it is
  the identical argument that justified local-first for text.
- `/engines` already reports voice privacy; make sure it reflects auto-detection rather than the
  raw env var.

## 3. Ship Piper voices, or fetch on demand?

**Resolution: fetch on demand, and pre-fetch the current target language in the background.**

Each voice is ~63 MB. Bundling several bloats the image; pure on-demand means the first use of a
language is slow *and needs the network* — the worst possible failure for a feature whose entire
selling point is not needing the network.

Act on it:
- Add a helper that downloads a voice for a language on first use, into `models/piper/`.
- When the workspace loads and local voice is active, kick off a background fetch for the current
  target language (same pattern as `prewarm_live()` — off the render path, failures silent).
- Never block a translation on a voice download: if it isn't there yet, use hosted TTS and say so.

## 4. Camera overlay — coloured section headings

**Resolution: leave it. Do not attempt a third heuristic without a better signal.**

The residual overlay error concentrates in burgundy-on-cream headings the greyscale threshold
misses. A per-channel ink map was tried and **reverted**: it found one more row plus a spurious
band over blank paper and measured no better.

Act on it:
- Treat this as needing a *different kind* of fix, not another threshold tweak — most likely real
  OCR geometry (Tesseract or PaddleOCR line boxes), which is a dependency decision, not a tuning
  one.
- Before any further work here, re-read the multi-run measurement discipline in §6: the whole
  reason this looked promising was a single-run number that didn't replicate.

## 5. Documents on a BYO profile + metering

**Done.** Documents route through the session profile via `ContextVar`; `passage/usage.py` counts
only metered work, in characters. Nothing further needed unless real accounts land, at which point
`usage` becomes a read against a `passage_usage` table keyed by uid and nothing above it changes.

## 6. Measurement discipline (applies to all of the above)

Anything whose result depends on a model's output must be measured **across multiple runs** before
the number is written down anywhere. An earlier overlay fix was reported as 17.5 px → 9.2 px from
one run; across five runs it was 23.5 → 20.5 px, better in 4/5. Report *median across N* and *how
many runs improved*, not a single before/after pair. Deterministic changes (masking, routing,
parsing) can be measured once — the distinction is whether sampling is in the loop.

## NEEDS DAVID — genuinely blocked

- **Supabase URL + anon key.** Auth verification is ported and live-tested against a throwaway
  project; the sign-in UI and any durable per-user storage need the real values. Both are designed
  to be public (they ship in every browser bundle), unlike the service-role key.
- **Whether traces get a UI, and what it shows.** `passage/traces.py` records document runs,
  machine output and human edits, and computes edit rate per engine. What to *display* — a
  per-segment timeline, an edit-rate dashboard, an LLM-as-judge view — is a product decision, and
  the plumbing was deliberately shipped without one.
- **Second-machine benchmarks.** Every latency figure in `RESEARCH.md` is one GPU's opinion. The
  *ranking* should travel; the absolute numbers should not be quoted as portable until someone
  runs the harness elsewhere. See `PORTABILITY.md` for the Apple Silicon analysis.
